# 资料库与全局资料入口设计

- 日期：2026-07-17
- 状态：已确认
- 分支：`feature/vault-credentials`
- 取代：`docs/superpowers/plans/2026-07-16-vault-ux-revamp.md`
- 参与者：SiChuchen + Codex

## 1. 概述

Soma Scratchpad 的核心仍是面向 AI 编程协作的桌面内容中转站。本次设计在现有临时“收纳”之外，增加一个长期、结构化的本地资料库，并通过独立的全局中央面板提供快速记录和自动混合检索。

本设计不把产品包装成密码管理器。资料库可以保存凭据、书签和笔记，但不承诺主密码、自动锁定或应用层加密。LLM 是资料库的核心智能层，负责录入整理、标签生成、检索元数据生成和自然语言查询理解；所有核心流程仍须在未配置、断网或模型失败时保持本地可用。

## 2. 已确认的产品决策

| 议题 | 决策 |
|---|---|
| 产品定位 | 本地资料库，不是加密保险箱 |
| 用户可见名称 | “资料库”；内部 Rust/TypeScript 模块名可继续使用 `vault` |
| 快速记录入口 | 独立的全局中央面板，不新增顶级“速记”Tab |
| 中央面板结构 | 显式“记录 / 搜索”双模式 |
| 录入策略 | 本地解析立即可用，LLM 自动增强但不阻断 |
| LLM 作用 | 生成标签和检索元数据；自动混合检索 |
| 搜索策略 | 本地即时结果 + LLM 查询理解 + 本地扩展召回 |
| 字段操作 | 每个标准字段和自定义字段均可单独复制 |
| 敏感字段 | 默认隐藏；眼睛图标切换显示；复制无需先显示 |
| 全局搜索布局 | 结果列表 + 详情双栏 |
| 主资料库布局 | 窄窗口单列，选中条目内联展开 |
| AI 设置名称 | “AI 整理与搜索” |

## 3. 为什么不能直接实施旧计划

### 3.1 信息架构与真实产品不一致

旧计划把产品描述为“收纳 / 速记 / 保险箱”三个顶级 Tab，但当前真实导航已经包含：

- 收纳
- 全部
- 收藏
- 保险箱
- 设置及窗口控制

主窗口默认宽度为 360px，最小宽度为 240px。继续插入“速记”会把一个动作与多个内容目的地混在同一导航层级，并进一步加剧横向拥挤。

### 3.2 “保险箱”与安全能力不匹配

当前 SQLite 数据文件及 LLM API Key 均没有应用层加密。“保险箱”会让用户自然期待主密码、锁定和静态加密，超出当前产品承诺。因此用户界面统一改称“资料库”。

### 3.3 旧录入 API 无法保存用户确认的标签

当前 `VaultEntryInput` 只有类型、标题、字段和备注，没有标签。旧计划要求预览页允许编辑标签，却仍调用 `createEntry()`；保存后又由 `ipc_vault_create_entry` 触发第二次异步打标。结果会是：

- 预览中确认的标签无法提交；
- 保存后产生另一套不可预测的标签；
- 同一条录入产生两次 LLM 调用。

### 3.4 当前 LLM 检索存在静默召回上限

`ipc_vault_llm_search` 只把最近的 100 条资料交给模型。超过上限的旧资料无法被 AI 找到，但界面不会告知用户。

### 3.5 当前脱敏规则与旧计划测试用例不一致

现有正则覆盖 PEM、JWT、URL 凭据、Bearer、长 Base64、AWS Access Key 和银行卡号，但不覆盖所有普通 `password=value`、通用 API Key 或 GitHub Token。旧计划以 `ghp_xxxxxxxxxxxx` 作为安全验证样例，按当前实现可能不会被替换。

### 3.6 LLM 配置没有在应用启动时加载

运行时的 `llm_config` 默认是 `None`，只有进入设置并调用 `ipc_vault_get_llm_config` 后才从数据库同步。应用重启后若用户不打开设置，自动打标和 LLM 检索会错误地表现为未配置。

## 4. 用户心智与信息架构

### 4.1 两个存储目的地

用户只需要理解两个存储目的地：

| 目的地 | 心智 | 生命周期 |
|---|---|---|
| 收纳 | 临时内容中转，用完即走 | 可自动清理 |
| 资料库 | 长期、结构化保存，便于再次查找和取用 | 持久保存 |

“全部”和“收藏”仍是收纳内容的组织视图，不是新的数据域。

### 4.2 全局资料入口不是存储目的地

全局中央面板是访问资料库的工具：

- 记录：把剪贴板或输入内容保存进资料库；
- 搜索：查找资料并复制单个字段；
- 不占用主窗口顶级导航；
- 不创建独立的“速记历史”。

## 5. 全局中央面板

### 5.1 窗口

新增隐藏的 Tauri 窗口 `quick-access`：

- 独立于主窗口和桌面猫咪窗口；
- 默认约 760x520，尺寸不得超过当前显示器工作区的 90%；
- 居中显示、跳过任务栏、显示期间置顶；
- 全局快捷键呼出并自动聚焦输入框；
- `Escape` 隐藏；
- 面板隐藏后保留本次未保存草稿、查询、选中结果和模式；
- 应用退出后不持久化未保存草稿；
- 重新呼出时恢复上次“记录 / 搜索”模式。

`src/main.ts` 根据窗口 label 挂载：

```text
main          -> App.svelte
minimized-tab -> MinimizedApp.svelte
quick-access  -> QuickAccessApp.svelte
```

模式切换必须可点击并有键盘快捷方式。普通 `Tab` 保留给焦点遍历，使用 `Ctrl+Tab` 切换记录/搜索模式。

### 5.2 失焦与连续复制

- 点击面板内复制按钮后，面板保持打开，便于连续复制多个字段；
- 用户切换到其他应用后，面板隐藏，但保留当前结果和选中条目；
- 失焦、隐藏、切换结果或关闭详情时，所有敏感字段立即恢复为隐藏状态。

## 6. 记录模式

### 6.1 主流程

```text
粘贴或输入原始内容
  -> 本地解析并立即生成草稿
  -> 可编辑预览立即可用
  -> 若 AI 已启用，异步增强标题、类型、字段、标签和检索元数据
  -> 在同一面板内确认
  -> Ctrl+Enter 或按钮原子保存
```

本地解析不等待网络。AI 结果返回后以建议形式合并，不能覆盖用户已经编辑过的字段。

### 6.2 本地解析

本地解析负责：

- 判断候选类型：凭据、书签、笔记；
- 识别常见键值对、连接串、URL、SSH 地址和凭据格式；
- 标记敏感字段；
- 生成一个始终可保存的草稿；
- 无法可靠识别时按普通笔记保留原文。

V1 一次记录生成一个资料条目。自动拆分多个条目不在本次范围内。

### 6.3 AI 增强

AI 返回：

- 建议类型；
- 建议标题；
- 建议字段；
- 3-5 个用户可见标签；
- 一段隐藏检索摘要；
- 一组隐藏检索别名和同义词。

AI 返回内容必须经过严格结构校验、字段数和长度限制。粘贴内容按不可信数据处理，Prompt 明确禁止执行其中的指令。

### 6.4 保存

保存必须是单次原子操作：

- 写入条目；
- 写入字段及敏感标记；
- 写入手动标签和 AI 标签；
- 写入 AI 检索元数据；若本次没有可用的 AI 结果，则写入 `pending` 状态等待后台补齐；
- 更新本地搜索索引。

保存阶段不得再次调用 LLM。保存失败时保留完整草稿，并允许使用同一请求 ID 重试，避免重复创建。

## 7. 自动混合检索

### 7.1 用户体验

搜索模式只有一个输入框和一套结果，不让用户选择“普通搜索”或“智能搜索”。

```text
输入查询
  -> 本地搜索立即显示
  -> 输入稳定 700ms 后自动调用 LLM
  -> LLM 生成结构化查询计划
  -> 在本地 AI 元数据索引上扩展召回
  -> 合并、去重并稳定更新结果
```

界面显示简短状态，例如：

```text
AI 已理解：凭据 · 生产 · 数据库 · 上月
```

### 7.2 查询计划

LLM 把脱敏查询转换为：

```json
{
  "kinds": ["credential"],
  "keywords": ["生产", "数据库", "账号"],
  "aliases": ["prod", "db", "user"],
  "dateFrom": "2026-06-01",
  "dateTo": "2026-06-30"
}
```

LLM 不接收完整资料目录。扩展查询仍在本地执行，从而避免每次搜索上传全部标题、标签和字段摘要。

### 7.3 合并与稳定性

- 本地精确匹配优先；
- AI 扩展结果补充召回；
- 按 entry ID 去重；
- 当前键盘选中的 entry ID 保持不变；
- 过期请求按查询版本丢弃；
- 后端取消或中止已过期的 LLM 请求，不能只在前端忽略结果；
- API Key 失效、限流或连续超时时进入冷却，避免每次按键重复失败。

### 7.4 搜索字段

本地搜索覆盖：

- 标题；
- 备注；
- 非敏感字段值；
- 用户标签；
- AI 标签；
- AI 摘要；
- AI 检索别名；
- 条目类型和时间范围。

密码、Token、私钥等敏感字段值不进入搜索索引。

中文搜索必须支持符合用户预期的前缀或子串匹配，不能仅以“使用 unicode61”作为验收标准。

## 8. 搜索结果与字段复制

### 8.1 全局面板

全局面板采用双栏：

- 左侧：结果列表；
- 右侧：当前条目的详情和全部字段；
- 方向键切换结果；
- 当前选中条目保持稳定；
- 标题、备注、每个标签以及每个标准/自定义字段值都能独立复制。

复制按钮可以在悬停或键盘聚焦时强化显示，以控制视觉噪声，但不能只依赖鼠标悬停才能操作。

### 8.2 主资料库

主窗口较窄，采用单列：

- 卡片默认显示类型、标题、关键摘要和标签；
- 选中后在卡片内展开字段；
- 不在列表中默认展开所有字段；
- 展开后标题、备注、标签和每个字段值均可独立复制。

### 8.3 敏感字段

- 默认使用掩码；
- 使用通用眼睛图标切换显示/隐藏；
- 每次只切换当前字段；
- 复制无需先显示；
- 反馈显示“已复制：密码”等字段名，不显示真实内容；
- 失焦、切换条目或关闭详情时自动隐藏。

标准字段和自定义字段使用同一个字段组件，不能只为密码、用户名等固定字段实现复制。标题、备注和标签虽然可以使用各自的展示组件，也必须遵守相同的独立复制与反馈规则。

## 9. 主资料库

### 9.1 Header

旧计划删除 LLM 搜索和智能导入后，仍保留四个筛选、搜索框和三个新建按钮，依然不适合 360px 窗口。

新 Header 分两行：

```text
[搜索标题、主机、用户名、标签................] [+ 新建]
[全部 24] [凭据 8] [书签 6] [笔记 10]
```

“+ 新建”打开类型菜单，不再并排放置三个按钮。

### 9.2 浏览与编辑

资料库负责：

- 浏览和筛选；
- 本地与自动混合搜索；
- 手动新建；
- 展开、复制和显示敏感字段；
- 编辑类型、标题、备注、字段、敏感标记和标签；
- 删除并提供撤销。

后端已有更新命令，但现有前端没有编辑入口。本次设计将编辑纳入必须范围。

## 10. 标签与 AI 检索元数据

### 10.1 标签来源

`vault_tags` 增加来源：

```text
entry_id
tag
normalized_tag
source: manual | ai
```

规则：

- 逻辑唯一键为 `(entry_id, normalized_tag, source)`，同一规范化标签可以同时存在手动和 AI 两种来源；
- 手动标签永不被 AI 删除；
- 重新分析时替换该条目的全部 AI 标签；
- 显示时按规范化文本去重；
- 用户新建或修改的标签记为手动来源；
- AI 标签不是简单与旧 AI 标签做永久并集。

### 10.2 AI 元数据

新增 `vault_ai_metadata`：

```text
entry_id PRIMARY KEY
summary
search_aliases_json
content_hash
provider_id
model
generated_at
status: ready | pending | error
```

`content_hash` 用于判断编辑后元数据是否过期。条目内容变化后，旧元数据不参与最终排序，并在后台重新生成。

标签、摘要和检索别名只能保存非敏感文本。后端不得把占位符还原进这些元数据；候选元数据若包含占位符、敏感字段原文或超出长度限制，则丢弃对应候选并记录可重试状态。

## 11. 脱敏与请求边界

### 11.1 请求级 TokenMap

TokenMap 不再作为应用全局状态保存。每次 AI 整理或查询使用独立映射：

- 请求结束立即释放；
- 占位符使用无语义的随机 ID；
- 同一请求内支持双向还原；
- 未知占位符视为验证错误，不允许保存。

### 11.2 自由文本脱敏

不能只复用现有七条正则。自由文本处理至少覆盖：

- `password/passwd/pwd/secret/token/api_key` 等键值对；
- GitHub 等常见 Token 前缀；
- PEM、JWT、Bearer；
- URL 内嵌凭据；
- AWS Access Key；
- 长 Base64；
- 用户在预览中手动标记的敏感片段。

结构化凭据优先只向 LLM 发送字段名称、非敏感上下文和占位符。对无法确定的自由文本，界面允许用户查看本次实际发送内容，不能用“绝对不会泄漏”替代可验证的边界。

### 11.3 查询脱敏

搜索查询同样经过自由文本脱敏。用户可能把 Token 误粘贴进搜索框，不得把原始查询直接交给 LLM。

## 12. 设置

### 12.1 信息架构

设置区名称为“AI 整理与搜索”，先说明能力和数据边界，再展示供应商参数。

默认展开内容：

- 连接状态；
- 自动整理与标签开关；
- 自动混合检索开关；
- AI 服务；
- API Key；
- 保存并验证；
- 删除配置；
- 数据发送说明。

高级内容：

- 模型；
- Base URL。

首次成功保存并验证配置后，两项 AI 能力默认开启，用户可以分别关闭。之后修改或重新验证配置不得擅自覆盖用户已有的开关选择。

### 12.2 数据说明

设置必须明确：

- 整理时发送用户可查看的脱敏文本；
- 检索时发送脱敏查询；
- 不上传完整资料库；
- 识别为敏感的字段原文不发送；
- API Key 保存在本机应用数据中；
- 当前数据文件没有应用层加密。

### 12.3 快捷键

提供两个独立快捷键并检查冲突：

- 显示/隐藏主窗口：默认 `Alt+Shift+V`；
- 打开全局资料入口：默认 `Alt+Shift+Space`。

### 12.4 剪贴板

默认启用“复制敏感字段后 30 秒清除”。仅当剪贴板内容仍等于应用刚复制的敏感值时清除，不能删除用户后来复制的新内容。

## 13. 前后端接口边界

建议新增或替换为以下职责明确的 IPC：

```text
ipc_vault_parse_capture_local(raw_text)
  -> CaptureDraft

ipc_vault_enrich_capture(draft, raw_text, request_id)
  -> AiCaptureSuggestion + AiRequestAudit

ipc_vault_create_from_capture(final_draft, request_id)
  -> VaultEntryDetail

ipc_vault_plan_search(query)
  -> AiQueryPlan

ipc_vault_search_hybrid_local(query, optional_plan, limit)
  -> VaultSearchHit[]

ipc_vault_refresh_ai_metadata(entry_id)
  -> accepted

ipc_vault_ai_backfill_status()
  -> progress
```

旧的目录上传型 `ipc_vault_llm_search` 不再作为前端备用路径保留。继续保留两个含义相近的 AI 搜索端点只会增加行为分叉。

`CaptureDraft` 至少包含：

```text
kind
title
notes
fields[]
manual_tags[]
ai_tags[]
ai_summary
search_aliases[]
warnings[]
```

`AiRequestAudit` 至少包含本次真正发送给供应商的脱敏文本预览、供应商、模型和发送时间。它用于界面中的“查看本次发送内容”，不包含 API Key，也不写入资料条目。前端不得用根据草稿重新推测出的文本冒充实际请求内容。

## 14. 配置与事件生命周期

- 应用启动时从数据库加载 LLM 配置并放入运行时状态；
- 删除配置时同时清除数据库和运行时状态；
- 前端事件监听在组件销毁时取消；
- 标签和 AI 元数据更新事件包含 entry ID、状态和最终数据；
- 禁止使用浏览器 `alert()`、`confirm()`；
- 使用统一 toast、内联错误和撤销机制；
- 错误消息面向用户，不直接展示供应商完整响应体。

## 15. 失败与降级

| 场景 | 行为 |
|---|---|
| 未配置 AI | 本地记录和搜索正常；显示配置入口 |
| API Key 失效 | 暂停自动 AI 请求；保留本地结果；引导修复 |
| 限流/超时/断网 | 本次降级并进入短暂冷却 |
| AI 返回非法 JSON | 丢弃 AI 建议；保留本地草稿 |
| 未知占位符 | 标记字段并阻止保存 |
| 数据库保存失败 | 保留草稿，使用同一请求 ID 重试 |
| 过期搜索响应 | 丢弃，不覆盖新查询 |
| AI 元数据过期 | 暂不参与最终排序，后台刷新 |
| 旧资料尚未补齐 | 本地搜索可用，界面显示后台整理进度 |

## 16. 迁移与旧资料回填

Schema 迁移必须兼容已有 `vault_entries`、`vault_fields` 和 `vault_tags`：

1. 为现有标签赋予来源。无法判断的现有标签按手动标签迁移，避免被 AI 删除。
2. 新建 `vault_ai_metadata`。
3. 重建或扩展本地搜索索引，使其包含 AI 元数据。
4. AI 启用后后台处理缺少元数据或 `content_hash` 过期的条目。
5. 回填可暂停、可重试，不阻断应用启动和本地搜索。

## 18. 验收标准

### 18.1 全局入口

- 快捷键稳定呼出并聚焦；
- 记录/搜索模式可见且可由键盘切换；
- “快捷键 -> 粘贴 -> Ctrl+Enter”可完成保存；
- 隐藏后草稿保留；
- 失焦和切换结果会隐藏敏感字段。

### 18.2 记录

- 本地预览不等待网络；
- 未配置、断网、超时和限流时仍可保存；
- 预览确认标签被原子保存；
- 保存不重复调用 LLM；
- 未知占位符不能写入数据库；
- 用户能查看实际发送的脱敏文本。

### 18.3 搜索

- 本地结果即时更新；
- AI 在输入稳定后自动运行；
- 用户不需要切换搜索引擎；
- AI 结果不会改变当前选中 entry ID；
- 超过 100 条的旧资料仍可召回；
- 中文前缀和子串搜索符合界面文案；
- 查询中的敏感值不出现在 LLM 请求体中。

### 18.4 字段

- 标题、备注、每个标签、IP、主机、端口、用户名、密码、URL 和自定义字段均可单独复制；
- 敏感字段默认隐藏并使用眼睛图标切换；
- 复制无需先显示；
- 通知不暴露真实值；
- 创建后可以编辑全部资料字段。

### 18.5 设置与生命周期

- 重启后无需打开设置页，AI 配置立即可用；
- 删除配置会停止后续 AI 调用；
- 两个全局快捷键分别配置并检测冲突；
- 反复进入资料库不会累计事件监听器；
- 不出现 `alert()`、`confirm()` 或未处理的异步错误；
- 360px 默认宽度和 240px 最小宽度无横向溢出；
- 中文和英文界面均完整。

### 18.6 测试要求

Rust 单元与集成测试至少覆盖：

- 自由文本敏感模式；
- 请求级 TokenMap 生命周期与回填；
- 未知占位符拒绝保存；
- 标签来源和重新分析替换规则；
- AI 元数据内容哈希和过期判断；
- 原子保存和幂等请求 ID；
- 查询计划校验；
- 超过 100 条的召回；
- 查询脱敏；
- 配置启动加载和删除。

前端自动或组件测试至少覆盖：

- 模式切换；
- 草稿在隐藏/显示间保留；
- 过期搜索结果不覆盖；
- 选中 entry ID 稳定；
- 每个字段复制；
- 眼睛图标只切换当前字段；
- 失焦后恢复隐藏；
- 设置状态和错误降级。

手动 Tauri 验证覆盖窗口焦点、全局快捷键、剪贴板自动清理、多显示器居中和主窗口最小宽度。
